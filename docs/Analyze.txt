  What This Changes Architecturally

  Three key differences from the original PRDs:

  1. AI does the heavy lifting from Day 1 — no "Wizard of Oz" manual scoping phase. The AI generates the scope, humans only refine. This means the AI pipeline is a Week 1 priority, not Week 5.
  2. Bid range instead of single estimate — the AI sets a floor and ceiling. Contractors compete within that band. This protects homeowners from overpaying AND protects contractors from a
  race-to-bottom. Much smarter than a single price point.
  3. Homeowner has real agency — they're not just accepting/rejecting. They can edit tasks, add context, and must explicitly approve before listing. This builds trust and improves scope
  accuracy with zero extra cost to you.

  Why This Beats Every Competitor

  - Thumbtack/Angi: Homeowner describes job in text → gets random bids with no scope alignment. You give them a visual, editable scope before any contractor is involved.
  - LawnStarter/GreenPal: Fixed SKU pricing, no customization. You let the job define the price, not a menu.
  - Everyone: Contractors bid blind. Your contractors bid on a reviewed, photo-documented, homeowner-approved scope with a price band. Higher close rate, less rework.

  Data Model — Universal Task Structure

  Every category produces the same task format:

  Task {
    id
    job_id
    category          → "lawn" | "patio" | "kitchen" | "bathroom" | "repair"
    title             → "Install paver patio"
    description       → "Remove existing concrete, install sand base..."
    photos[]          → extracted frames / uploaded photos for THIS task
    estimated_qty     → 200
    qty_unit          → "sq_ft" | "linear_ft" | "each" | "hours"
    materials[]       → [{ name, qty, unit_cost, quality_tier }]
    labor_hours_est   → 16
    cost_range        → { min: 1200, max: 1800 }
    sort_order        → 3
    homeowner_notes   → "I want a curved edge, not straight"
    ai_confidence     → 0.85
  }

  Job {
    id
    homeowner_id
    category
    subcategory       → "paver_install" | "mowing" | "full_remodel"
    media[]           → original uploads
    tasks[]           → AI-generated, human-refined
    starting_bid      → sum of all task minimums + margin
    max_bid           → sum of all task maximums + margin
    timeline_est      → { min_days: 3, max_days: 5 }
    status            → "ai_scoping" | "review" | "homeowner_approval" |
                         "listed" | "bidding" | "assigned" | "in_progress" |
                         "completed"
    location
    quality_tier      → "budget" | "standard" | "premium"
  }

  Why One Universal Flow Works

  The beauty is that from the contractor's side and homeowner's side, the experience is identical regardless of category:

  1. Upload media → see AI-generated tasks with photos
  2. Edit/approve tasks
  3. See bid range
  4. Approve to list
  5. Contractors bid within range
  6. Pick a contractor
  7. Track progress per task
  8. Pay on completion

  The only thing that changes is what the AI looks for and what pricing data it references. The UI, the flow, the bidding mechanics, the payment system — all the same.

  This means you build the platform once and add new categories by:
  - Adding category-specific AI prompts/detection rules
  - Adding local pricing data for that category
  - Recruiting contractors in that category
